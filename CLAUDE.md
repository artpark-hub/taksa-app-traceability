## Project Overview

Taksa Traceability is a Go backend service for manufacturing execution (MES) — tracking products, materials, equipment, and operators through a factory. Built with **Go Kratos v2**, **gRPC + HTTP REST** (dual protocol from proto definitions), **GORM** ORM, and **PostgreSQL 15 + TimescaleDB**.

## Build & Development Commands

```bash
make init          # Install protoc plugins, kratos CLI, wire CLI (first-time setup)
make api           # Generate gRPC/HTTP stubs + OpenAPI from api/traceability/v1/traceability.proto
make config        # Generate config structs from internal/conf/conf.proto
make generate      # Run go generate ./... && go mod tidy
make all           # Full code generation: api + config + generate
make build         # Build binary to ./bin/

# Run locally (requires env vars: DB_USER, DB_PASSWORD, DB_HOST, DB_PORT, DB_NAME)
go run ./cmd/traceability -conf ./configs/config.yaml

# Run tests (builds server, starts it, runs Bruno integration suite, cleans up)
./run_tests.sh

# Run tests manually
cd tests/api && npx @usebruno/cli run --env "Dev VM"

# Run specific test folder
cd tests/api && npx @usebruno/cli run 15_Queries --env "Dev VM"

# Regenerate test .bru files (uses timestamps for unique test data)
python3 generate_tests.py
```

## Architecture (Clean Architecture / DDD)

Request flow: **proto → service → biz (usecase) → data (repository) → PostgreSQL**

| Layer | Location | Responsibility |
|-------|----------|----------------|
| Proto/API contracts | `api/traceability/v1/traceability.proto` | Single source of truth for all 64+ RPC methods and HTTP mappings |
| Transport | `internal/server/` | HTTP (port 8000) and gRPC (port 9000) server setup |
| Service | `internal/service/traceability.go` | Proto request/response ↔ domain model translation; no business logic |
| Business logic | `internal/biz/traceability.go` | Domain models and `TraceabilityUsecase`; framework-agnostic |
| Data/Persistence | `internal/data/traceability.go` | GORM ORM models, repository implementation, DB queries |
| Config schema | `internal/conf/conf.proto` | Proto-defined config loaded from YAML |
| Entry point | `cmd/traceability/` | Bootstrap, Wire DI wiring |
| DB schema | `database/schema/` | DDL for all tables; `traceability_log` is a TimescaleDB hypertable |

**Dependency injection** uses Google Wire (compile-time). Each layer exports a `ProviderSet` in its package-level `*.go` file. `cmd/traceability/wire_gen.go` is auto-generated — never edit it.

## Domain Model

**Plant hierarchy:** Enterprise → Site → Area → ProductionLine → ProductionUnit → Equipment

**Equipment system:** EquipmentClass (type/template) → EquipmentMaster (physical instance, string ID like "MIXER-001") with capabilities and properties.

**Material tracking:** MaterialDefinition → MaterialLot (batches with quantity/status). LotGenealogy tracks parent→child lot transformations via work orders.

**Operations:** WorkOrder links equipment + operator + input lots → output lot. TraceabilityLog records time-series events (TimescaleDB hypertable).

**Key queries:** TraceBackward (final product → raw materials), TraceForward (raw material → downstream products), TraceFullGenealogy (complete graph).

## Adding a New Feature

1. Define RPC + messages in `api/traceability/v1/traceability.proto` (with `google.api.http` annotation)
2. `make api` to regenerate stubs
3. Add domain model in `internal/biz/traceability.go`, add usecase method
4. Add ORM model + repository method in `internal/data/traceability.go`
5. Implement service handler in `internal/service/traceability.go` (translation only)
6. Add DB table in `database/schema/` if needed
7. Add test in `generate_tests.py`

## Generated Files (never edit manually)

- `cmd/traceability/wire_gen.go` — Wire dependency injection output
- `api/traceability/v1/*.pb.go` — Proto-generated gRPC/HTTP code
- `internal/conf/conf.pb.go` — Proto-generated config structs
- `openapi.yaml` — Generated OpenAPI spec
- `tests/api/**/*.bru` — Generated by `generate_tests.py`

## Testing

Tests are **integration tests** using Bruno (open-source API client with `.bru` text files). The Python script `generate_tests.py` dynamically generates all test files with unique timestamps to avoid collisions. Tests are organized in numbered folders (01_Enterprise → 99_Cleanup) with a dependency chain where IDs are passed between requests via `bru.setVar()`.

## Configuration

YAML configs in `configs/` use environment variable substitution (`${DB_USER}`, etc.). `config.yaml` for local dev, `config_docker.yaml` for containers. Server listens on HTTP :8000 and gRPC :9000.
